# ZK-106 — Durable browser ciphertext synchronization

State: DONE (PR open / review pending)
Priority: P1
Source: https://github.com/rheavenza/zk-note/issues/3
Target: `master`

## Objective

Wire the web client's encrypted IndexedDB state to the existing sync API through the shared Rust/WASM sync rules, including push, pull, restart, retry, and conflict preservation.

## Dependencies

ZK-105, existing sync protocol/engine, browser IndexedDB adapters, and the authenticated session from ZK-104.

## Acceptance criteria

1. The app supplies a real authenticated sync adapter; invoking sync without one cannot mark the server as synced or advance `last_sync_at`.
2. Each local create/edit/delete queues a durable ciphertext mutation with a stable idempotency ID and correct expected revision. Accepted replay does not create a second revision.
3. Push honors server CAS responses. Stale edits and delete-versus-edit cases retain the local edit and an actionable conflict record; tombstones are not silently resurrected.
4. Pull applies pages in server sequence order and advances the cursor only after each encrypted object is durably stored. Network/storage failure resumes without skipped changes.
5. Locked pulls store ciphertext only; decrypt and local search updates happen after unlock through the shared core. No plaintext crosses the network or persists in the local note cache.
6. Account/server switching isolates sync cursor, pending queue, and encrypted objects; no cross-account upload or pull occurs.

## Implementation details

- `BrowserSyncAdapter` (`apps/web/src/sync/adapter.ts`):
  - Communicates directly with authenticated backend endpoints `POST /v1/sync/push` and `GET /v1/sync/pull`.
  - Enforces Zero-Knowledge validation (`validateNoPlaintextSecrets`) on all outgoing/incoming payloads to guarantee SEC-001/SEC-002 invariants.
  - Automatically wired into `SyncProvider` (`apps/web/src/context/SyncContext.tsx`) when the browser vault has an active authenticated session and matching vault link (`serverOrigin`, `accountId`).
  - Stale edits and delete-vs-edit produce actionable `ConflictRecord`s stored in IndexedDB (`storage.putConflict`) with base, local, and remote encrypted envelopes without silent overwrites (SEC-006 / SEC-008).
  - Pull operations apply changes in sequence order and durably commit encrypted objects before advancing the sync cursor in storage (preventing skipped changes across crashes).
  - Safe operation during locked vault state: ciphertext is persisted directly into IndexedDB without invoking decryption keys or touching plaintext search indexes (SEC-009).
  - Strict HTTP 409 handling: differentiates `ERROR_MUTATION_REPLAY_MISMATCH` (fails closed, preserves mutation intact without bogus conflict record) from `ERROR_REVISION_CONFLICT`.
  - Multi-edit offline protection: stops pushing subsequent dependent mutations for an object if an earlier mutation for that object encounters a conflict.
  - Conflict data-loss prevention: `storage.putConflict` commits durably first, and conflicting mutations remain recoverable in the mutation queue marked `Pending` (matching Rust `push_pending_changes`).
- Shared Rust/WASM Core Ownership (`crates/zk-sync` and `crates/zk-wasm`):
  - Decoupled `zk-sync` native adapter dependencies (`reqwest`, `tokio`, SQLite), enabling compilation to `wasm32-unknown-unknown`.
  - Exposed `record_conflict`, `generate_merge_candidate`, and `build_conflict_record` across the WASM boundary.
  - Web Worker calls `session.record_conflict()` to generate line-level diff3 merge candidates and conflict records using shared Rust core logic.
- Physical Multi-Identity Isolation (`apps/web/src/storage/indexeddb.ts` and `apps/web/src/App.tsx`):
  - `getScopedDatabaseName()` physically isolates IndexedDB databases per `(serverOrigin, accountId)`.
  - `App.tsx` dynamically scopes storage creation to the authenticated session and remounts providers on account switch (`key={storageKey}`).
  - Scoped `getSyncState()` / `setSyncState()` / `setSyncCursor()` by `(serverOrigin, accountId)` identity.
  - Added `resetInFlightMutations()` to safely reset crashed/abandoned mutations to `Pending` on browser restart.
