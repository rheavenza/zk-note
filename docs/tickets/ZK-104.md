# ZK-104 — Web authentication and compatible origin

State: IN_REVIEW
Priority: P1
Source: https://github.com/rheavenza/zk-note/issues/3
Target: `master`

## Objective

Make a browser session authenticate against a configured server and make the web origin compatible with the server's WebAuthn relying party. Keep the vault usable offline without an account.

## Dependencies

Existing WebAuthn server contracts, browser auth adapter, and ZK-103 browser vault lifecycle. No new server authentication protocol is planned.

## Acceptance criteria

1. A user can register or sign in from the web UI, see authenticated/expired/offline states, and sign out without losing the local vault.
2. Account and session state are bound to the selected server origin. Changing origin never silently reuses a session or vault association.
3. WebAuthn works on a documented same-origin or RP-compatible HTTPS deployment. A development origin that cannot satisfy the configured RP ID shows an actionable explanation before a ceremony.
4. No passphrase, vault key, note plaintext, recovery key, or full bearer token enters logs, URLs, or server sync payloads. Existing device/session authorization rules remain in force.
5. Auth errors and offline operation are visible; neither is reported as a successful sync.

## Verification

Run `cd apps/web && npm run lint && npm run typecheck && npm test && npm run build`. Add browser auth tests for registration, sign-in, expiry, origin mismatch, sign-out, and offline use. Perform a real browser WebAuthn smoke test on an RP-compatible HTTPS origin and record the origin pattern without publishing private deployment details.

## Artifacts and fallback

Update web setup/deployment documentation and attach redacted browser test evidence to the implementation PR. If a live RP-compatible endpoint is unavailable, complete automated tests with a local RP-compatible HTTPS harness and leave live smoke verification explicit; do not relax RP validation.
