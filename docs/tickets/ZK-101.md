# ZK-101 — Add lazygit-style interactive terminal UI

State: READY
Priority: P1
Source: https://github.com/rheavenza/zk-note/issues/1
Target branch: `master`
Base commit: `16497d18a59cc540db0187bec6a141ac78a6b489`
Worker branch: `ag/ZK-101` (bridge-internal); publish as `work/ZK-101-terminal-ui`

## Objective

Add a full-screen, keyboard-first terminal interface to the existing `zk-note`
binary, launched with `zk-note tui`, using Ratatui 0.29 and Crossterm 0.28.
The TUI is a presentation layer over the existing native client behavior. It must
preserve every existing non-interactive CLI command and must not duplicate or
reimplement cryptography, storage, synchronization, conflict resolution,
authentication, vault, editor-safety, or auto-lock rules.

## Dependencies

- Repository milestones through ZK-099 and the Cloudflare backend task ZK-100

- In particular, ZK-027 local search, ZK-040–ZK-046 sync, ZK-050–ZK-057

## Required design

1. Add `ratatui = "0.29"` and `crossterm = "0.28"` without raising the current
   Rust 1.80 MSRV solely for this work.
2. Keep the implementation in `apps/cli` and the existing `zk-note` binary.
3. Extract the smallest coherent set of reusable, non-printing native client
   services needed by both current Clap handlers and the TUI. The TUI must not
   shell out to CLI subcommands. Rendering/event code must remain separate from
   domain/client operations.
4. Use an explicit UI state machine with navigation, search, editing,
   confirmation, conflict, help, locked, and terminal-too-small states. Secret
   and plaintext-bearing state must not derive unrestricted `Debug`.
5. Manage raw mode and the alternate screen through an RAII terminal guard.
   Restore the terminal on normal exit, returned errors, and panics; clear
   rendered plaintext before returning to the shell where practical.
6. Reuse existing encrypted SQLite, in-memory search, guarded/CAS sync,
   conflict-resolution, secure external-editor, authentication, and auto-lock
   paths. Do not create plaintext caches, snapshots, ordinary temp files, new
   server endpoints, or background write paths.

Suggested module boundaries may be adjusted to fit the codebase:

```text
apps/cli/src/client/       reusable non-printing application services
apps/cli/src/tui/app.rs    UI state and modes
apps/cli/src/tui/action.rs semantic actions
apps/cli/src/tui/event.rs  input/tick handling
apps/cli/src/tui/ui.rs     rendering
apps/cli/src/tui/terminal.rs terminal lifecycle guard
apps/cli/src/tui/views/    notes, note, conflict, locked, help views
```

## Functional acceptance criteria

- AC-01: `cargo build --release --bin zk-note` succeeds and `zk-note tui`
  starts a full-screen interface. Existing commands, flags, stdout/stderr
  behavior, and JSON modes remain script-compatible.
- AC-02: At 80x24 or larger, the main view exposes a notes pane, selected note
  preview/editor pane, metadata pane, and contextual status/key-hint bar. It
  shows vault, sync, conflict, note-selection, and active-mode state.
- AC-03: Navigation supports `j`/Down, `k`/Up, Enter, `g`, `G`, Tab,
  Shift+Tab, Esc, `?`, and `q`, with safe selection behavior for empty and
  non-empty vaults.
- AC-04: The locked view accepts a masked passphrase unlock, supports explicit
  lock, respects the existing idle auto-lock policy, and immediately clears all
  decrypted note, edit, preview, conflict, and search state when locked.
- AC-05: `/` provides incremental, local-only search over existing in-memory
  search behavior. Search text and indexes are neither persisted nor sent to a
  server, and are cleared on lock.
- AC-06: Users can list, open, create, inline-edit, and delete notes. Delete is
  confirmation-gated. An explicit shortcut invokes the existing secure
  `$EDITOR` workflow; no ordinary plaintext temporary file is introduced.
- AC-07: `s` manually invokes the existing guarded sync path and displays at
  least offline/unauthenticated, idle, syncing, synced, conflict, and error
  states. This ticket adds no automatic background writes outside that path.
- AC-08: `c` opens unresolved conflicts and shows the note identity/title,
  local and remote revisions, and the existing merge candidate where available.
  Keep-local, accept-remote, merge, and duplicate actions call existing
  `zk-sync` conflict operations and preserve CAS/tombstone safety.
- AC-09: Terminal resize never panics. Below the supported layout size the UI
  collapses panes or renders a clear terminal-too-small view.
- AC-10: No note plaintext, title, tag, attachment metadata, search term,
  passphrase, key, recovery key, or full authorization token is added to logs,
  persistent UI state, local plaintext storage, or server payloads. Clipboard
  and OSC52 support are absent.
- AC-11: Documentation covers launch/build instructions, locked/unlocked
  behavior, the complete keybinding cheat sheet, external-editor behavior, and
  responsive constraints in `apps/cli/README.md` and the root CLI section.

## Required automated coverage

- Ratatui `TestBackend` rendering tests: locked screen, populated notes, empty
  vault, active search, delete confirmation, conflict view, help overlay, and
  terminal-too-small view.
- State/action tests: upper/lower navigation boundaries, `g`/`G`, focus cycling,
  mode transitions, search update/clear, delete confirmation/cancellation,
  manual sync dispatch, and conflict-action mapping to existing client services.
- Security state test: locking and auto-lock zeroize or clear every decrypted
  TUI/search/edit/conflict buffer and make the previous content unreachable
  through subsequent rendering.
- Terminal lifecycle tests use an injectable/mock terminal adapter to prove raw
  mode and alternate-screen cleanup on success and error. Add a panic-path test
  where practical without mutating the developer's real terminal.
- CLI regression tests prove representative existing commands and JSON output
  remain compatible after service extraction.
- All fixtures must be synthetic and contain no real user content.

## Verification commands

Run from repository root and report each command and result in the PR:

```bash
cargo fmt --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test -p zk-cli
cargo build --release --bin zk-note
cargo test --workspace
./scripts/ci.sh
```

Also perform a local pseudo-terminal/manual smoke using a disposable data
directory and synthetic notes:

1. Launch `zk-note tui` while locked and unlock through the masked prompt.
2. Exercise list/open/search/create/edit/delete confirmation/help/resize/lock.
3. Exercise manual sync in unauthenticated or disposable local test mode.
4. Exercise the conflict screen using synthetic fixture data if a disposable
   two-client setup is impractical.
5. Quit normally and force one handled error; verify terminal echo, cursor, raw
   mode, and alternate-screen state are restored.
6. Inspect the disposable directory and logs for forbidden plaintext.

## Out of scope

- Mouse-first interaction, image/attachment previews, rich Markdown rendering,
  plugins, clipboard/OSC52, recovery/passphrase-management screens, replacing
  the current CLI, a Go implementation, server changes, protocol changes, or a
  new sync engine.

## Fallback and stop conditions

- If reusable service extraction would require a protocol/envelope/KDF change,
  a weakened security invariant, or new plaintext persistence, stop and return
  a `BLOCKED / SPEC QUESTION` handoff with the exact conflict. Do not improvise
  cryptography or weaken SEC-001 through SEC-010.
- If the full ticket cannot remain one coherent reviewable CLI change, stop
  before partial UI behavior is presented as complete. Propose dependency-ordered
  slices that preserve all acceptance criteria, with the service extraction and
  terminal lifecycle shell as the first slice.
- Preserve the existing non-interactive CLI as the functional fallback. Do not
  remove, silently alter, or route it through an incomplete TUI path.
